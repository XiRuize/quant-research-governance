# 清洗范式卡 · 索引

> **给后续 AI 研究员的入口。** 这里放的不是流程，是**踩过的坑**：每张卡都对应一次真实事故，
> 写清了「什么时候必须想起它」「照做的话怎么写」「不照做会怎样」「怎么机械验证」。
>
> 契约（`spec/cleaning.spec.json`）说**规则是什么**；范式卡说**为什么会有这条规则、违反时数字会怎样错**。
> 两份都要读，但顺序是：先读卡，再读契约，否则契约里的键名记不住。

## 怎么用

| 你在做什么 | 先读 |
|---|---|
| 新接入一批原始表 | P07（去重/单位）→ P06（板块）→ P11（黑名单） |
| 建行情面板 / 建因子 | P01（网格）→ P02（复权）→ P08（时间对齐） |
| 用财务或行业字段 | P04（财务 PIT）→ P05（行业 PIT） |
| 做组合构建 / 报 Sharpe | P09（缩尾中性化）→ P10（执行成本）→ P12（评估语义）→ P03（涨跌停锁死） |
| 写「数据缺口」结论 | P11（先测填充率，再判缺） |
| 引用历史结论 | `spec/run.spec.json` → `run.json.caliber`，确认成本口径 |

## 三条元规则

1. **一条卡只写一个坑。** 卡里出现「另外顺便注意」就是该拆卡了。
2. **新卡必须有事故。** 没有真实事故做支撑的规则不立卡——它属于"最佳实践"，属于 `docs/`，不属于这里。
3. **卡和契约必须双向可查。** 每张卡末尾列 `契约块:`；契约的每个块也应能指回卡片（见各块 `note`）。

## 与其它规范的关系

```text
spec/cleaning.spec.json   规则（唯一口径来源，可被代码加载）
paradigms/*.md            规则的来由与代价（人读）
rules/*.json              阈值与制度参数（机器读）
spec/run.spec.json        研究产物怎么归档
spec/registry.spec.json   数据集怎么登记
```
