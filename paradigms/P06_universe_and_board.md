# P06 股票池与板块：跨表合并前先按 board 过滤

**一句话**：A 股不是一张表，是主 / 科创创业 / 北交所三张表；不同来源的表覆盖的板块不一样，直接 inner join 会静默改变样本。

## 触发

- 合并任意两张以上的股票级表；
- 声明"全市场"；
- 计算涨跌停幅度（板块决定幅度）。

## 规则

1. 板块按代码前缀三分，不按简称、不按交易所：

| board | 前缀 | 涨跌停 |
|---|---|---|
| `main` | 60 / 00 | 10% |
| `star_chinext` | 68 / 30 | 20% |
| `bse` | 8 / 4 / 920 | 30% |

2. 代码白名单只允许 6 位；非 6 位"幽灵码"在**数据层**剔除，不留给研究层过滤。
3. 跨表合并前必须**逐表统计 board 分布**，不一致的不得当同一股票池。
4. 任何结论必须声明股票池（全市场 / 中证800 / 自定义），池子不同不可比。

## 反例

`yjbb` 的 12 月期里 `bse_neeq`（新三板）有 **50,216 行**，A 股只有 **45,979 行**——样本被撑到 2.1 倍；而 `lrb` / `xjll` 不含新三板。四张报表 universe 完全不同，直接 inner join 会得到既不是 A 股也不是新三板的第三种样本，且没人会发现。

同一批数据里 `first_board_events` 也不等于"全部首板"：79,608 / 85,853 = **92.8%**，因为只保留了 T+1 开盘可买的子集。取用它做"首板胜率"会把买不到的 7.2% 直接删掉，胜率被系统性抬高。

## 证据

- `数据源/README.md` §10"引用这批表前必须知道"第 2、5 条（实测行数）
- `research/16_daban_limit_up/runs/QM-20261102-072/`：85,853 首板，可买 92.8%
- 契约块：`universe_and_board`

## 检查

```python
dist = panel.groupby("board").size()
assert set(dist.index) <= {"main","star_chinext","bse"}
assert panel.code.str.len().eq(6).all()
# 跨表合并前：两表 board 分布必须同构
assert abs(a.groupby("board").size() / len(a) - b.groupby("board").size() / len(b)).max() < 0.02
```
