# 人机分工（AI 协作下的清洗标准）

本文件把蓝图里「人机分工」8 条落成工程约束。核心原则：

> **AI 在边界，代码在主干；AI 只提议，代码才落库。**
> **LLM 只在“入库前”出现，绝不出现在回测/在线路径里。**

## 三档划分

| 档位 | 归属 | 本库中的模块 |
|---|---|---|
| ① 代码硬边界 | 必须确定性、可哈希、可复现 | 复权、网格、PIT 时点、制度日历、费用/冲击/容量、产物 hash、门禁 |
| ② AI 候选制 | 只产出候选 + 置信 + evidence_ids，低置信不落库 | 事件抽取、实体消歧、事件-标的映射、字段映射建议、异常解释 |
| ③ 人机混合 | AI 提议 → 人审 → 代码固化 | 制度规则、来源白名单、尾部情景库、映射强度表、测试生成 |

## 五条判据

1. 重跑必须逐位一致 → 代码
2. 错了会静默传导到净值 → 代码 + 门禁
3. 输入是自然语言/长尾半结构化 → AI（候选）
4. 规则每年变且变在文本里 → AI 发现、人审、代码执行
5. 规模 × 频率高（百万行/日）→ 代码

## 工程约束

- **回放可验证**：任何被 AI 影响的字段，都必须能通过“截断回放”检验（见 `qrg.clean.lookahead.replay_check`）。
- **AI 产物版本化**：模型、prompt_hash、seed、input_hash、output_hash 必须随数据一起落库；否则 `f-vintage` 管不住它。
- **职责分离**：抽取 agent 与校验 agent 不得是同一实例；门禁判定不得由 AI 执行。
- **可降级**：没有模型时，规则通道必须能独立跑通（本库默认无任何 LLM 依赖）。
- **摘要不是证据**：只有「归档原文 + 内容 hash + 抓取时间」才是证据。

## 本库当前状态

v0.1 全部为档位 ①，不含任何 LLM 调用。文本/事件层（G 层）在 v0.2 引入，届时按上述约束接入。
